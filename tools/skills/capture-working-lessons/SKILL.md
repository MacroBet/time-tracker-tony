# Capture working lessons

Preserve what changed how to do the work, with evidence and scope. Keep detailed
context in the originating project; this skill contains the general method only.

Read the applicable project instructions and existing index, current state and
lesson log first. Reuse them; do not create parallel backlogs or reread the entire
chat when a focused delta and linked evidence suffice. Respect the user's requested
format and the task at hand; capture must not replace completing authorized work.

At a meaningful close within an applicable teaching/recap request, save only new,
substantiated lessons and the tangible outcome. Distinguish:

- An explicit user rule or correction, including what it supersedes.
- A preference or decision specific to this project, recipient or situation.
- An interpretation or untested hypothesis that must not become a general rule.
- Technical evidence: an artifact, reproducible check, commit or verified external
  state. Positive feedback alone proves neither correctness nor deployment.

For each useful addition record source/date, scope, the behavior to change, observed
result/evidence, limits and the next resumption point. A short table or paragraph
in established project docs is enough. Link fuller sources rather than copying
transcripts. If no new lesson is supported, make no lesson entry.

Maintain one authoritative current state and a small discoverable index. Link a
project recap/lesson log from its existing bootstrap instructions when needed for
future work. An ordinary question should still receive its requested answer,
without unrelated implementation or wholesale context loading. A request about a
different project must use that project's context, never a previous client's data.

Before treating a technique as reusable, check whether the evidence supports it
beyond this one case. Do not infer universal prices, permissions, technologies or
communication styles from a single successful project. Keep secrets, financial
account details, unrelated conversations and ambient transcripts out of saved notes.

This workflow adds no permission to message others, spend money, write to remote
systems, provision credentials or run in the background. Preserve current approval
boundaries and qualify historical permissions that have been revoked. Do not create
schedules or global instructions unless the user specifically requests them and
they are necessary. No separate installation is required in the user's projects.

Conclude briefly with what was captured, its exact location and material limits.
When no persistent file access exists, state that limitation rather than promising
memory across sessions. Update incrementally after later demonstrated corrections.
